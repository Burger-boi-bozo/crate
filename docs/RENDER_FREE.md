# Free hosted converter at down.dpifiles.org

This deployment uses **one Render Free Python web service**. Cloudflare supplies DNS for the existing domain; it does not run the converter. There is no dependency on Proxmox, R2, a paid database, or a separate worker.

## Deploy

[Deploy Crate to Render](https://render.com/deploy?repo=https://github.com/Burger-boi-bozo/crate)

1. Sign in to Render and select the intended workspace. Keep its plan at Hobby, the service instance at Free, and do not add a payment method if zero charges is a hard requirement.
2. Review the Blueprint. It contains exactly one service, `crate-down`, with `plan: free`.
3. Deploy. The build installs Python dependencies and verifies FFmpeg, ffprobe, and Node. Render's [native runtime includes FFmpeg and Node](https://render.com/docs/native-runtimes).
4. Keep the generated `CRATE_SESSION_SECRET` private. Visitors need no account or access code; an old `CRATE_ACCESS_CODE` variable from earlier deployments is ignored and may be removed.
5. Open the **actual onrender.com URL returned by Render** and paste a link. Do not assume the name is available or invent its final URL.

An account sign-in, workspace choice, and initial DNS setup are unavoidable account steps. The button provides the service configuration automatically; it cannot grant account permissions or change Cloudflare DNS.

## Custom domain

The Blueprint declares `down.dpifiles.org`. If the service was created directly instead of through the Blueprint, first add that hostname in **Render → service → Settings → Custom Domains**. Merely committing `render.yaml` does not attach a directly created service to a Blueprint.

In Cloudflare's `dpifiles.org` zone, use the exact target shown by Render:

| Setting | Value |
| --- | --- |
| Type | CNAME |
| Name | `down` |
| Target | The service's actual `*.onrender.com` hostname |
| Proxy status | DNS only (grey cloud) |
| TTL | Auto |

Inspect existing records first. Replace only conflicting records for `down.dpifiles.org`, including an AAAA record for that exact name if present. Leave all other domain records alone. Return to Render, verify the domain, and wait for its automatic HTTPS certificate. See [Render custom domains](https://render.com/docs/custom-domains).

Check both the provider URL and `https://down.dpifiles.org/api/health`. Then submit a short permitted public clip and verify the downloaded file plays. A successful homepage or health response alone does not prove YouTube access from Render.

## What “free” means

Render's [free-service documentation](https://render.com/docs/free) describes a monthly pool of 750 free instance hours, idle sleeping, and usage limits. Excess bandwidth can be billed if a payment method exists. Without one, Render suspends free services at the bandwidth limit; exhausted build minutes disable new builds. These limits are shared with other services in the workspace. High service-initiated network usage can also cause suspension.

The converter limits jobs, file sizes, retries, runtime, and download requests to keep casual use small. Its counters and queue are in memory and reset on restart; they do not enforce a persistent billing cap. A free compute selection by itself is not a promise of unlimited free bandwidth. Do not upgrade or enable billable resources to resolve a quota failure.

Free instances sleep after 15 minutes without traffic and take about a minute to wake. Local files disappear on sleep, restart, or deploy. Crate deletes completed files after one hour even if the process remains active; history stays only in the browser. Do not add keep-alive services to evade sleeping.

## Implementation and maintenance

- Entry point: `python -m app.serve`, bound to `0.0.0.0:$PORT` with one process.
- Requirements: `requirements-converter.txt`; Python/Node versions in `render.yaml`.
- Secret: `CRATE_SESSION_SECRET`, generated by the Blueprint, signs anonymous browser cookies.
- Media storage: `/tmp/crate-converter`, one isolated directory per conversion.
- DNS and TLS: Cloudflare DNS only plus Render-managed HTTPS.
- Source URLs: public HTTP(S) pages handled by yt-dlp's site and generic extractors; private network destinations are blocked. No user-supplied downloader flags, proxies, cookies, or shell commands. Subscription music links get an explicit limitation instead of a misleading preview download.
- Output: H.264 MP4 up to 1080p (including portrait video), or MP3 at 128 kbps; 10 minutes and 100 MB maximum. Codec conversion stays within the free instance's time and storage bounds.
- Failed jobs expose distinct error codes. Service logs include redacted provider diagnostics so hosted-IP blocks can be distinguished from format or conversion failures.
- The runner uses urllib with DNS checks, disables external network downloader fallbacks, bounds time/disk/CPU, and restricts FFmpeg input protocols and demuxers.
- Keep yt-dlp and its EJS dependency updated together. Its transport override is intentionally pinned and covered by a test. Test real hosted media access after updates; different sites change independently.
- This simple public converter exposes no torrent, general URL-proxy, or legacy administration endpoints. The original local manager remains available separately.

Run `python -m pytest -q` with `requirements-dev.txt` and FFmpeg installed. Tests cover anonymous browser isolation, unsafe sources/private DNS destinations, queue limits, cleanup, cancellation, file delivery, 1080p format selection, codec fallback, resolution bounds, and real MP4/MP3 conversion from generated clips. Remote extraction requires a separate smoke test from the deployed service.
